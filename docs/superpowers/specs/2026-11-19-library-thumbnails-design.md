# 主列表只给屏幕里的行出缩略图

## 目标

视频库主列表停稳后，只给当时真正出现在屏幕里的行加载缩略图。屏幕外即使已经被列表排上，也保持占位，滑进来并停稳后再加载。滚动过程中不出新图。滑出屏幕、还没完成的加载取消。

缓存里已有的图马上显示。这一行已经显示的图，滑出屏幕后不清掉。

## 决定

主列表用纯函数 `thumbnailShouldLoad(isScrolling, itemKey, visibleKeys)`，按这个顺序：

- `isScrolling` 为真：不加载。这一条优先于可见行。
- `itemKey` 在 `visibleKeys` 里：加载。
- 其余：不加载。可见行为空时也不加载。

`visibleKeys` 是主列表当前已经排出来的可见项 key。露出一点的行也在这个集合里。函数本身不测量像素。

列表还没完成第一次布局时，可见行是空的，先保持占位。布局出来之后，没在滚动就给当时可见的行加载。

传给函数的 `itemKey` 必须是这一行在 `LazyColumn` 里使用的同一个 key。最近播放、分类栏、空状态和分组标题不走这个函数。

`VideoListScreen` 把 `deferThumbnailLoad` 设为这个函数的否定。剧集详情仍只按是否正在滚动推迟加载。最近播放仍马上加载。

## 取消和失败

这一行不再该加载时，`deferThumbnailLoad` 变为真，正在进行的加载协程取消，结果不写进这一行。

阻塞解码如果在取消被观察到之前已经写进缓存，缓存留着。下次这行又该显示时，已有的图马上出来。这一行上已经显示的图保持显示。

平台缩略图和帧回退都拿不到图时，这一行保持现在的占位。不增加失败文案。这行一直可见时，不反复重试。滚出屏幕再滚回来之后，按新的一次加载再试。帧回退仍是现在的 400 毫秒后再试一次，而且只在这行仍然该加载时进行。平台图并发仍是最多 3 个，帧回退仍是 1 个。

## 测试

纯函数覆盖：正在滚动且 key 可见、没在滚动且 key 可见、没在滚动且 key 不在可见行里、正在滚动且 key 不在可见行里、没在滚动且可见行为空。测试不使用 Compose，也不使用 Robolectric。取消和界面组合不进这个测试。
